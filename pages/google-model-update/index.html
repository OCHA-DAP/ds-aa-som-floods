Somalia Riverine Flood Trigger / operational note

The new Google model and the Gu windows

Google has released a new version of the flood model behind Flood Hub (November 2026). The two Gu windows run on Google. This page replays them on the new model with exactly the method used to design them on the old one: the same seven points, the same March–May season, the same 1999–2023 calibration years, the same return periods and vote counts. Only the per-point levels are refitted, on the new model's own record. The Deyr windows and the readiness leg run on GloFAS and do not change. 4 November 2026.

1What changes

  • Activation years. Gu Juba: 2013, 2016, 2018, 2020 on the old model, 2016, 2018, 2020 on the new. Gu Shabelle: 2013, 2016, 2018, 2020 on the old, 2016, 2018, 2020, 2023 on the new. Both windows drop 2013, which the river gauges did not record as a Gu flood season on either river; the Shabelle adds 2023, a severe Gu season on the gauges.
  • Timing. Wherever both models meet the rule in the same year, on the record or on the forecasts, the new model meets it later: by 2 to 10 days. The detail per year is in the timing tables below.
  • All four windows together (Deyr unchanged on GloFAS version 5, as designed): 8 activations (1-in-3.2) on the old model, 7 (1-in-3.7) on the new; severe years caught 7 and 7 of 7; activations outside a flood season: 2013 and none.
  • Levels. The new model runs higher at these points, so the levels rise: Juba points 1.7–2.1 times the old levels, Shabelle points 1.2–1.3 times. Its March–May flows track the SWALIM gauges about as well as the old model on the Juba (median correlation 0.86 → 0.88) and better on the Shabelle (0.79 → 0.89).
  • Same years throughout. Every old-versus-new comparison on this page uses only the years both versions cover: the record 1999–2023 (the calibration years) and, for forecasts, the Gu seasons 2016–2023. The new model's 2024 and 2025 are reported separately in section 6.
Before Google switches Flood Hub to the new model. On 4 November 2026 the Flood Hub API still serves the old model (same gauge identifiers, unchanged warning levels). The monitoring pipeline reads Google with Gu levels fitted on the old model, frozen in the pipeline's threshold file. If the API moves to the new model before those levels are refitted, the old levels would sit far below the new model's ordinary Gu flows: on the new record they would have activated Gu Juba in 12 and Gu Shabelle in 5 of the 25 Gu seasons 1999–2023. The refitted levels are the "new level" columns below. Signals that the switch has happened: Flood Hub's warning levels or gauge model identifiers change for these gauges, or the gauge identifiers move from hybas_ to subhybas_ as in the new dataset (not confirmed).

The windows were calibrated jointly to about 1-in-3 on the old model. On the new model the same settings activate less often (1-in-3.7). Whether to re-tune for the new model is a design decision for the working group; this page only shows the adopted settings carried over.

7Method

  • Exactly the trigger page's code (scripts/page_additions/somlib.py), run on each model's data in turn: per-point levels by Weibull plotting position with log-log interpolation on March–May maxima 1999–2023; a day counts when at least the required number of points are at or over their own level; forecasts at leads 1–7 days against the same levels.
  • Same years for both versions: levels fitted on 1999–2023 for both; activations, timing, scores, correlations and the old-levels-on-new-flows count all over 1999–2023; forecasts over the Gu seasons 2016–2023.
  • The river-gauge benchmark is unchanged (two SWALIM gauges over their own level, levels fitted 2000–2023).
  • The old model run here reproduces the adopted Gu activation years (2013, 2016, 2018, 2020 on both rivers).
  • Data: Google Runoff Reanalysis & Reforecast, public Google Cloud bucket flood-forecasting, old version model_id_8583a5c2_v0, new version distributed_model_2026_11 (CC-BY-4.0).
